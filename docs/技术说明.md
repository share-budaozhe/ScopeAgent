## 1. 总体架构

ScopeAgent 采用 **「Qt 宿主进程 + Agent Sidecar 独立进程」** 架构，二者通过本地 HTTP/JSON 通信。核心设计目标是把「LLM 的自然语言推理」与「仪器的确定性控制」解耦，并用双层校验保证 LLM 的不可信输出永远不会越界。

```
┌────────────────────────── Qt 宿主 (C++ / Qt 5.12) ──────────────────────────┐
│  MainWindow ──┬── WaveformWidget   （网格 / 辉光轨迹 / 触发线 / 刻度，~30FPS）│
│               ├── 读数面板 / 手动设置 / 自然语言输入 / SCPI 连接 / 日志      │
│               └── AgentClient      （QProcess 拉起 sidecar + HTTP 异步调用）  │
│  IDriver 抽象 ──┬── VirtualScopeDriver （虚拟合成波形）                      │
│                └── ScpiDriver          （真实仪器 VISA/SCPI 骨架）            │
│  DeviceConfig   （配置结构体 + JSON 序列化 + 范围钳制，Qt 侧兜底）            │
└────────────────────────────────┬───────────────────────────────▲────────────┘
                    HTTP/JSON (127.0.0.1:8765)                 │
                                  ▼                              │
┌────────────────────────────────┴───────────────────────────────┴────────────┐
│  Agent Sidecar (Python 3.10，纯标准库，可打包为独立 exe)                     │
│  server.py      HTTP 服务（/health、/v1/configure、/mcp）                    │
│  agent.py       function-calling Agent 循环（≤6 轮）                          │
│  deepseek_client.py   DeepSeek 客户端（urllib，OpenAI 兼容）                  │
│  tools.py       工具集（get_spec / get_state / configure_scope）             │
│  schema.py      DeviceConfig 契约 + validate_config 钳制                     │
│  mcp_server.py  MCP 服务端（stdio + HTTP，额外暴露 acquire 工具）             │
└────────────────────────────────┬────────────────────────────────────────────┘
                                 │ function calling
                          DeepSeek API (deepseek-v4-pro)
```

**模块职责边界**：

| 模块 | 语言 | 职责 |
|---|---|---|
| `app/src/*` | C++ | GUI、驱动抽象、sidecar 管理、配置的第二层钳制 |
| `app/drivers/*` | C++ | `IDriver` 实现（虚拟 / SCPI） |
| `agent/server.py` | Python | HTTP 入口、配置加载（env + config.json） |
| `agent/agent.py` | Python | 编排 function-calling 多轮循环 |
| `agent/tools.py` | Python | 工具定义与执行（读写当前状态） |
| `agent/schema.py` | Python | **契约唯一权威定义** + 第一层钳制 |
| `agent/deepseek_client.py` | Python | DeepSeek HTTP 客户端 |
| `agent/mcp_server.py` | Python | 将同一套能力暴露为 MCP 工具 |

**核心设计原则**（引自 PR，贯穿全文）：

1. **Agent 只建议，Qt 是唯一 truth source** —— LLM 输出必须经 schema 校验 + 范围钳制后才下发。
2. **契约先行** —— 两侧共享同一份 `DeviceConfig` 字段定义（JSON snake_case 传输）。
3. **驱动可插拔** —— 所有驱动实现 `IDriver`，Agent 不感知底层是虚拟还是真实仪器。
4. **零第三方 Python 依赖** —— 交付即用。

## 2. 数据流

### 2.1 自然语言驱动（在线主链路）

用户输入一句中文意图 → 波形与读数实时变化，完整链路：

```
用户输入 "显示 1kHz 方波，时基 200µs，触发电平 0.5V"
  │  MainWindow::onSendIntent()                       mainwindow.cpp
  ▼
AgentClient::configure(intent, state.toJson())          agentclient.cpp:150
  │  POST http://127.0.0.1:8765/v1/configure
  │  body = { "intent": "...", "state": {当前配置} }
  ▼
server.py Handler.do_POST() → validate_config(state)    server.py:97
  │  ① 先对 Qt 上报的状态做一次钳制，保证 Agent 输入合法
  ▼
agent.py run_agent(intent, state, client)               agent.py:28
  │  循环 ≤ MAX_TURNS=6 轮：
  │    DeepSeek 依次调用 get_spec → get_state → configure_scope
  │    每次 tool_calls 由 tools.py::execute_tool_calls 在本地执行并回填
  │    configure_scope 的参数经 validate_config 钳制后写入 ctx.final_config
  ▼
返回 { ok, config, rationale, confidence, model, tool_calls }
  ▼
AgentClient 收到响应 → 发出 configured(result) 信号      agentclient.cpp:163
  ▼
MainWindow::configured 槽                               mainwindow.cpp:53
  │  DeviceConfig::fromJson(config, 当前状态)  ← Qt 侧再次钳制（第二层）
  │  applyConfig(cfg, "Agent") → m_currentDriver->apply(cfg)
  ▼
IDriver::apply()  → WaveformWidget::update() 重绘
  │  VirtualScopeDriver：更新 m_cfg，供 acquire() 合成波形
  │  ScpiDriver：生成 SCPI 命令并下发（未连接时静默）
  ▼
波形 / 读数 / 日志（rationale、工具调用链、最终配置）更新
```

### 2.2 手动 / 离线链路（不依赖 Agent）

无 API Key 或断网时，右侧「手动设置」面板直接改配置，完全不经过 sidecar：

```
拖动 SpinBox / 切换 Combo
  │  MainWindow::onManualChanged()                      mainwindow.cpp:288
  ▼  configFromControls() → DeviceConfig
  ▼  applyConfig(cfg, "手动") → driver->apply() → 波形更新
```

> 注意 `m_syncing` 标志：`syncControlsFromConfig()` 回填控件时会触发 `valueChanged`，用 `m_syncing` 抑制「回填 → 又触发手动下发」的回环。

### 2.3 启动链路

```
MainWindow 构造 → AgentClient::start()                   agentclient.cpp:47
  │  findAgentDir() 定位 sidecar 目录（exe 同目录/../agent/../../agent/cwd 下找 server.py）
  │  优先 scopeagent-sidecar.exe（打包 exe），否则 python server.py
  │  QProcess 启动（Windows 下 CREATE_NO_WINDOW 隐藏控制台）
  ▼  QTimer 每 400ms 轮询 /health（最多 30 次 ≈ 12s 超时）
  ▼  ready=true → 状态栏 "Agent 在线（deepseek-v4-pro）"
```

### 2.4 MCP 链路（标准化接入）

任意 MCP 客户端（Cursor / Claude Desktop / 其他框架）以 stdio 或 HTTP 方式拉起 sidecar，通过 4 个标准工具驱动示波器，数据流同「2.1」但绕开 Qt 宿主，由 `mcp_server.py` 内部的 `ToolContext` 持有状态并本地合成 `acquire` 样本。

## 3. 接口

### 3.1 DeviceConfig 契约（两侧共享）

JSON 传输字段（snake_case）与 C++ 成员（camelCase）映射关系及合法范围：

| JSON 字段 | C++ 成员 | 类型 | 范围 | 默认 |
|---|---|---|---|---|
| `waveform` | `waveform` | enum | sine/square/triangle/sawtooth/noise | sine |
| `frequency_hz` | `frequencyHz` | double | 1 ~ 10_000_000 | 1000.0 |
| `amplitude_vpp` | `amplitudeVpp` | double | 0.01 ~ 100 | 3.0 |
| `dc_offset_v` | `dcOffsetV` | double | -100 ~ 100 | 0.0 |
| `sec_per_div` | `secPerDiv` | double | 5e-7 ~ 1.0 | 5e-4 |
| `volts_per_div` | `voltsPerDiv` | double | 0.005 ~ 20 | 1.0 |
| `trigger_level_v` | `triggerLevelV` | double | -100 ~ 100 | 0.0 |
| `trigger_slope` | `triggerSlope` | enum | rising/falling | rising |
| `noise_level` | `noiseLevel` | double | 0 ~ 1.0 | 0.02 |

> **⚠ 契约同步是维护本项目的第一要务**：该契约在 `agent/schema.py`（`CONFIG_FIELDS` + `SCOPE_SPEC`）与 `app/src/deviceconfig.h/.cpp` 各定义一份。新增/改名字段必须**同时修改两处**。

### 3.2 HTTP API（sidecar，Base URL `http://127.0.0.1:8765`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查，返回 `{ok, ready, version, model, base_url}`；`ready` 表示是否已配置 API Key |
| POST | `/v1/configure` | 自然语言 → 配置（见下） |
| POST | `/mcp` | MCP JSON-RPC 2.0 端点（streamable HTTP） |

`/v1/configure` 请求 / 响应：

```jsonc
// 请求
{ "intent": "测量 1kHz、3Vpp 正弦波，触发稳定一点",
  "state":  { "waveform": "sine", "frequency_hz": 1000.0, /* ... 当前配置 ... */ } }

// 响应（200）
{ "ok": true,
  "config":    { /* 已钳制/校验的最终配置 */ },
  "rationale": "1kHz 正弦波周期 1ms，时基设 200µs/div 显示约 2 个周期……",
  "confidence": 0.92,
  "model": "deepseek-v4-pro",
  "tool_calls": ["get_spec", "get_state", "configure_scope"] }

// 错误：400 缺 intent / 非法 JSON；502 DeepSeek 调用失败；503 未配 API Key；500 内部错误
```

### 3.3 MCP 工具（JSON-RPC 2.0，协议版本 `2024-11-05`）

| 工具 | 参数 | 返回 |
|---|---|---|
| `get_spec` | — | 能力规格（带宽/采样率/波形/各档位范围） |
| `get_state` | — | 当前配置 + 可读摘要 |
| `configure_scope` | DeviceConfig 字段 + 必填 `rationale` | 校验后的配置 + 钳制告警 |
| `acquire` | `points`（10~100000，默认 1000） | 当前配置下合成的波形样本数组 |

接入：stdio 用 `python agent\mcp_server.py`（或 `scopeagent-sidecar.exe --mcp`），HTTP 用 `POST /mcp`。客户端配置示例见 `agent/mcp_config.example.json`。

### 3.4 IDriver（C++ 驱动抽象）

定义于 `app/src/deviceconfig.h`：

```cpp
class IDriver {
public:
    virtual ~IDriver() = default;
    virtual QString id() const = 0;                       // "virtual" / "scpi"
    virtual QString name() const = 0;                     // 显示名
    virtual DeviceConfig state() const = 0;               // 读当前配置
```

### 3.5 配置加载优先级（sidecar）

环境变量 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` / `DEEPSEEK_BASE_URL` **优先于** `agent/config.json`。三者默认：`deepseek-v4-pro`、`https://api.deepseek.com`。缺 Key 时 `/v1/configure` 返回 503，Qt 侧进入离线手动模式（这是**受支持状态**，非错误）。

## 4. 核心原理

### 4.1 双层钳制校验（对抗 LLM 幻觉）

LLM 输出被视为完全不可信，在**两个进程、两个层级**分别校验：

1. **第一层（Python）** `agent/schema.py::validate_config()`：对 `configure_scope` 的参数做数值范围钳制（`_clamp_number` 夹到 `[min,max]`，NaN/Inf/非数回退默认）、enum 白名单校验；缺失字段继承当前状态 `base`；并附一条软约束告警（时基相对频率过慢时提示）。
2. **第二层（C++）** `app/src/deviceconfig.cpp::DeviceConfig::clamped()`：与第一层**镜像**的钳制逻辑，作为 Qt 侧兜底——即使 sidecar 被绕过/出 bug，下发的配置也一定合法。

```python
# agent/schema.py —— 钳制核心
def _clamp_number(value, lo, hi, default):
    try: v = float(value)
    except (TypeError, ValueError): return default
    return max(lo, min(hi, v))          # 夹到 [lo, hi]
```

`confidence` 作为输出可信度信号：Agent 若成功调用了 `configure_scope` 则为 0.9，否则 0.4（说明只是文字回答、未产生结构化配置，用当前状态兜底）。

### 4.2 Function-Calling Agent 循环

`agent.py::run_agent` 用 OpenAI 兼容的 tool 协议编排多轮对话（`MAX_TURNS = 6`）。系统提示词（`SYSTEM_PROMPT`）固定引导模型按 **预研 → 读状态 → 生成配置** 的顺序：先 `get_spec` 了解能力、`get_state` 了解现状，再按领域知识计算（时基 = 周期/目标周期数，屏幕显示 1~2 个周期；垂直档位 = 峰峰值/2~4 格；触发电平取波形中段），最后 `configure_scope` 一次性下发。工具在**本地执行**（`tools.py`），模型只产出结构化参数，不接触任何设备 IO。

### 4.3 波形合成与触发相位对齐

虚拟示波器（`virtualscopedriver.cpp`）按配置实时合成波形，行为模拟真实示波器：

- **五种波形**：sine / square / triangle（`asin(sin)` 三角）/ sawtooth（`2*(ft-floor(ft+0.5))` 锯齿）/ noise（零均值）。
- **触发相位对齐** `findTriggerPhase()`：在 `[0, period)` 内以 N=4000 细分搜索首个满足触发斜率、穿越触发电平的时刻 `t0`，采集起点从 `t0` 开始——保证屏幕波形从触发点起稳定显示、不抖动。
- **动态噪声**：`std::mt19937` 以 `steady_clock` 为种子，每帧噪声不同，呈现真实示波器「活」的刷新观感。

> 该合成逻辑在 `mcp_server.py::synth_samples()` 中**独立复刻了一份**（固定种子 `random.Random(12345)` 保证可复现），使 MCP `acquire` 与 GUI 波形一致。改波形算法需**同步两处**。

### 4.4 辉光轨迹渲染

`waveformwidget.cpp` 用 `QPainter` 自绘，无第三方 UI 依赖：

- **网格**：10 列 × 8 行主格，每格 5 细分次格（点线），中央十字轴。
- **坐标映射**：`y = 中心 - (电压 / voltsPerDiv) * 每格像素`；`x = 左 + i/(N-1) * 宽`。
- **辉光效果**：同一条 `QPainterPath` 先以 5px 半透明青绿画「辉光层」，再以 1.6px 实色画「亮线层」，两笔叠加产生 CRT 荧光感。
- **刷新**：`QTimer` 33ms（≈30FPS）触发 `update()`。

### 4.5 SCPI/VISA 动态加载

`scpidriver.cpp` 通过 `LoadLibraryA("visa64.dll")`（回退 `visa32.dll`）+ `GetProcAddress` **运行时**加载 VISA，避免链接期依赖 visa 库（未装 VISA 时优雅降级为「未连接」，不崩溃）。`apply()` 将配置映射为 SCPI 命令（`:CHANnel1:SCALe` / `:TIMebase:SCALe` / `:TRIGger:EDGE:LEVel` 等）；`acquire()` 为骨架，需补全 `:WAVeform:DATA?` 解析即可接真实仪器。

### 5.4 波形合成与触发对齐（`virtualscopedriver.cpp`）

```cpp
double VirtualScopeDriver::findTriggerPhase() const {
    // 在 [0, period) 内搜索首个满足触发斜率、穿越触发电平的相位偏移
    for (int i = 0; i < N; ++i) {
        double t = i * dt;
        double v1 = signalCore(t), v2 = signalCore(t + dt);
        if (rising) { if (v1 <= trig && v2 > trig) return t; }
        else        { if (v1 >= trig && v2 < trig) return t; }
    }
    return 0.0;
}

QVector<double> VirtualScopeDriver::acquire(int points) const {
    double span = m_cfg.secPerDiv * 10.0;      // 屏幕横向 10 格
    double dt = span / points, t0 = findTriggerPhase();
    for (int i = 0; i < points; ++i)           // 从触发点开始采样
        out[i] = signalCore(t0 + i * dt) + noise;
    return out;
}
```
